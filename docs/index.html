Funcionalidades

Qué puede hacer SpringBank

Un motor bancario completo con gestión de usuarios, cuentas y transacciones. Control de acceso por roles y registro de auditoría en cada operación.

Autenticación JWT

Inicio de sesión seguro con access token de corta duración y refresh token persistente. Revocación instantánea al cerrar sesión. Sin sesiones en servidor.

  • JWT
  • BCrypt
  • Refresh Token

Gestión de Cuentas

Creación de cuentas de ahorro y corriente con número único generado de forma segura. Consulta de saldo y control de acceso por propietario.

  • JPA
  • MySQL
  • SecureRandom

Transacciones

Depósitos, retiros y transferencias entre cuentas con validación de saldo e historial completo. Cada operación queda registrada con fecha y descripción.

  • @Transactional
  • BigDecimal
  • Historial

Control de Roles

Dos roles diferenciados: CLIENTE y ADMIN. Cada endpoint valida que el usuario solo pueda operar con sus propios recursos.

  • @PreAuthorize
  • RBAC
  • Spring Security

Documentación API

Documentación interactiva generada automáticamente con OpenAPI 3 y Swagger UI. Permite probar todos los endpoints directamente desde el navegador.

  • OpenAPI 3
  • Swagger UI
  • springdoc

Pruebas Automatizadas

Suite de 83 tests unitarios que cubren servicios y controladores. Uso de Mockito para aislar dependencias y JUnit 5 para las aserciones.

  • JUnit 5
  • Mockito
  • MockMvc

Seguridad

Capas de protección

La seguridad no es un módulo: está integrada en cada capa de la aplicación.

01

Filtro JWT por request

Cada petición HTTP pasa por JwtAuthenticationFilter, que valida el token, verifica que no esté revocado y carga el contexto de seguridad antes de llegar al controlador.

02

Tokens revocables en base de datos

Cada token se almacena con su estado (expired, revoked). Al hacer logout o login nuevo, todos los tokens anteriores quedan invalidados inmediatamente.

03

Contraseñas con BCrypt

Ninguna contraseña se almacena en texto plano. BCrypt aplica un factor de costo adaptativo y un salt automático por cada hash generado.

04

Validación de propiedad de recursos

Un cliente solo puede operar con sus propias cuentas. Cada endpoint de transacción verifica que la cuenta pertenezca al usuario autenticado antes de ejecutar la operación.

05

Validación de entrada (Bean Validation)

Todos los DTOs de entrada usan anotaciones de validación (@NotBlank, @NotNull, @Size, @Positive). Errores de validación retornan respuestas estructuradas con HTTP 400.

06

Manejo centralizado de errores

GlobalExceptionHandler captura todas las excepciones y devuelve respuestas JSON coherentes con código de error, mensaje y ruta — sin stack traces expuestos.
